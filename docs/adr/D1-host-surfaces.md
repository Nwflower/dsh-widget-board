# D1. 只走宿主扩展点

## 背景

上一个插件（dsh-claude-style）大部分成本花在宿主没有开放扩展点的地方：效果靠覆盖宿主的 DOM 与样式实现，依赖宿主没有承诺过的结构，宿主每改一版就要重新核对一遍假设。组件看板是一块新的表面，宿主已经为这类表面准备了扩展点：侧栏的全局面板列表、中栏的键位页面、会话里按工具名分派的工具视图、右侧栏的标签页类型、服务注册、工具注册、路由注册、存储域。任务看板插件已经用前两处做出了同样形态的页面。

## 决定

- 插件只通过宿主扩展点接入：插槽、服务、事件、路由。不写宿主选择器，不在插件自己的根节点之外查询或修改文档；lint 执行这一条。
- 四处界面表面：`sidebar.panellist`（侧栏入口）、`main` 的键位页面（看板页）、`tool.call.toolview`（会话里的组件视图）、`sidebar.right.pane.tab`（固定到右侧栏）。每一处都经 `ctx.slots.inject` 注册，插件与宿主外壳的加载次序无关，外壳不提供某个插槽时那一处表面缺席，其余照常。
- 宿主插槽名、服务名、事件名，以及从宿主读来的值的形状，只在 `packages/contracts` 的契约表里写一次：每一项写明它的含义、所在的宿主包、核实时的宿主版本与契约测试怎么检查它。代码只经契约表里登记的访问器读宿主。
- 宿主已经提供的能力不另做一份：持久化用存储域，执行用 `ptcRuntime` 与 `subprocess`，批准用 `approval`，主题用宿主的令牌与主题事件，外壳控件用宿主的界面原语。
- 宿主服务可能缺席时，用可选链与类型判断表达缺席，并在界面或工具结果里给出可见的说法；缺席不让插件启动失败。
- 外壳元素写语义属性 `data-dsh-widget-*`，皮肤插件可以据此定位；插件不读其他插件的标记。

## 后果

- 宿主扩展点的形状改变时，契约测试在真实宿主上第一个失败，改动只发生在契约表与它的访问器里。
- 宿主没有开放的能力（例如把卡片置顶成独立的桌面窗口）只能做能力探测与入口，不能靠覆盖层补齐。
- 放弃的方案：在会话页面里直接插入卡片 DOM。代价是放弃了宿主没有开放插槽的位置。

## 重审条件

- 宿主开放置顶窗口、桌面小组件或插件级 iframe 托管能力时，改为接入宿主的。
