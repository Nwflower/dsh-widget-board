# D10. 令牌与动效

## 背景

组件要好看且彼此一致，又要跟随宿主的主题与皮肤：用户装了皮肤插件时，组件应当随皮肤的配色变化。上一个插件的经验是：同一个时长、曲线或颜色写在样式表、脚本常量与文档几处，改一处就漏一处；令牌只有一份来源时，这类问题才消失。

## 决定

- 令牌只有一份来源：`packages/contracts/tokens.json`。外壳样式表、运行时套件与文档里的令牌表都由它生成。时长、缓动曲线、层级只从令牌读。
- 组件令牌（`--w-color-bg`、`--w-color-fg`、`--w-color-accent`、圆角、间距、字号阶梯）是宿主 `--dsw-*` 令牌的别名。宿主令牌传不进不透明来源的 iframe，所以浏览器半边把别名解析成字面值：握手时经 `init` 递一次，之后宿主主题事件触发时经 `theme` 消息再推一次（D18）。
- 解析只在一处：`client/src/theme.ts`。同一次解析的动画档位与界面语言跟令牌一起推给每张卡。
- 一种效果只有一档：需要新的时长或曲线时先挑已有的一档，挑不到再加一档。
- 动效原语在运行时套件里实现：数字滚动、文字变形、图标切换、骨架闪烁、列表重排。组件用类名声明，不各自实现。
- 动画档位在运行时合成：系统要求减弱动效时一律减弱，否则听宿主推来的值；原语与外壳读同一个值。
- 卡片移动与缩放的过渡由外壳画，时长与曲线从令牌读；展开与收起用 View Transitions（D16）。

## 后果

- 宿主改名或删除某个 `--dsw-*` 令牌时，别名表在契约测试里失败。
- 组件作者写自定义动画时，必须在 `prefers-reduced-motion` 下给出静止状态；尺寸矩阵会在减弱动效下渲染一次并检查静置。
- 宿主没有主题服务时，外壳退到系统的配色与动画偏好，皮肤引起的变化这时收不到。

## 重审条件

- 宿主公开动效令牌与层级令牌时，这两组改为别名到宿主的。
- 宿主提供插件级的 iframe 托管或可继承令牌的来源时，令牌不必再解析成字面值。
