# D11. 快速失败与可见故障

## 背景

被吞掉的错误会在别处以更难排查的方式出现：界面少了一块，控制台什么也没有。上一个插件只能把功能的失败写进控制台，因为它画在别人的表面上。组件看板画在自己的表面上，故障可以直接显示给用户，组件代码又常常由 agent 现写，出错是常态。

## 决定

- 错误在发生处抛出，不吞掉、不静默回退。宿主服务可能缺席时，用可选链与类型判断表达缺席，不用捕获错误。
- 允许捕获错误的每一处，都在代码旁边写明理由。
- 需要隔离的地方报告后继续：逐个通知订阅者、逐个运行数据源与刷新任务、逐张卡片渲染，其中一个失败只影响它自己。
- 故障在它所属的表面上可见：组件的脚本错误、超时、数据校验失败、权限被拒，都显示在那张卡片上，带具体原因与「交给 agent 修复」；原生组件由错误边界隔离并同样显示。宿主一侧的故障在工具结果里以 `ok: false` 返回。
- 拆除是一切建立之物的唯一清理点：监听、订阅、端口、定时器、注册的插槽与工具。拆除最先注册，可以重复运行。

## 后果

- 每处捕获都要写理由，代码因此更长。
- 卡片上的故障信息来自组件代码与数据，按外来字符串处理（D3）。

## 重审条件

- 宿主提供插件级的错误上报时，宿主一侧的报告接过去。
