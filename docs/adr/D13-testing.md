# D13. 测试分层与共用检查器

## 背景

上一个插件把检查堆在一条通道里时，改一个文件也要付出整条通道的等待；断言写成钟点与像素量值时，同一份代码在忙碌的机器上失败。组件看板还有一个独有的问题：组件的数量会不断增长，每个组件、每个尺寸族、每种配色都要显示正确。agent 写组件时需要的检查，与持续集成需要的检查，是同一件事。

## 决定

- 测试只有一个入口 `npm run verify`，按「读什么」分档：不读构建产物的检查与单元层同批起跑，读构建产物的浏览器层在构建之后同批起跑。
- 各层只回答它能回答的问题：
  - 单元层（Vitest，node）：`model` 的断点、像素范围、推导、装箱、降级；manifest 校验；协议与桥消息的解析；存储迁移；`.dshw` 的打包、解包与路径校验。
  - 浏览器单元层（Vitest 浏览器模式）：桥的握手、运行时接口、CSP 违规的捕获、动效原语在减弱动效下静置。
  - 尺寸矩阵（Playwright）：每个组件 × 每个尺寸族 × 像素范围的两端 × 浅色与深色 × 中文与英文，外加一次减弱动效；判定无脚本错误、无溢出、无 CSP 违规、非空、在限时内静置。
  - 端到端（真实宿主，`.debug/` 下独立的 `DSH_HOME`）：入口与页面的注册、工具的往返、会话内联渲染、固定到右侧栏、展开浮层、重启后恢复、SSE 断线重连、导入导出。
- 尺寸矩阵与 agent 的自检（D9）调用同一个检查器，判定规则只写一次。
- 组件是矩阵的输入：内置组件与 `packages/testing/fixtures/` 里的组件（包括故意出错的组件，用来证明检查器能抓住它们）自动进入矩阵，加组件不需要写测试代码。
- 断言读用户能观察到的结果：属性、文字、元素在不在、尺寸关系。钟点阈值、帧数与单个像素量值不进断言；限时只用来让卡住的等待按名字失败。
- 截图由矩阵写到运行的输出目录，供人工在浅色与深色下核对，不作为自动判定。

## 后果

- 矩阵的规模随组件数相乘增长，需要按并发度分片运行。
- 行为层需要本机装有宿主；没有宿主的机器只能跑到尺寸矩阵为止。

## 重审条件

- 宿主提供官方的插件测试环境时改用宿主的。
