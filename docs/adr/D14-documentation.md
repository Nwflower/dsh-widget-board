# D14. 文档分层

## 背景

同一件事实写在几处时，读者无法判断哪一处还有效，改动时也总有人漏掉一处。上一个插件在长大之后才把文档按归属分开，期间大段文字随着一次不改变方向的重构过期。

## 决定

- 每一类信息只放在一处：机制、执行顺序、路径与数值属于代码与注释；全局结构与跨模块不变量属于 `ARCHITECTURE.md`；方向性选择属于 `docs/adr/`；面向用户的行为属于双语 README 与它旁边的用户文档；命令与红线属于 `AGENTS.md`；宿主接入面的核实记录属于 `docs/host-surfaces.md`。
- 判断一段文字归属的测试：一次不改变方向的重构会不会让它过期。会过期的文字留在代码旁边。
- ADR 只记录当时选了什么方向、为什么、放弃了什么，写下之后不随代码修改，不写现状与进度。
- 方向被推翻时另写一条 ADR，写明它取代的编号；被取代的文件删除，编号作废、不复用。
- 一条方向的理由无法从代码与测试读出来时，它才够格成为 ADR；能由工具执行的规则写进检查。
- 行为变化在 `docs/changes/` 加一个文件，CHANGELOG 的 `[Unreleased]` 段由脚本从这些文件生成。
- 实施计划是一次性文档：`docs/PLAN.md` 在全部完成后删除。

## 后果

- 想了解机制的人要读代码，文档不替他复述。
- 被取代的 ADR 已经删除，遇到作废编号时要顺着取代它的那一条读。

## 重审条件

- 无。
