# D15. 信息流看板布局

- **取代**：D4

## 背景

看板上的卡片是形状差别很大的小组件：天气卡要一块竖长的天空，番茄钟要一段控件面板。按固定的列与行给每张卡一片格子，卡片的高度就由格子决定，组件只能去填满一个自己没选过的盒子；参考链接里的组件都是按内容定高、按宽度换排版的卡片。用户要的是信息流：卡片一列列往下排，屏幕变宽多一列，变窄少一列。

## 决定

- 看板是一列列往下排的信息流。列数由看板容器的宽度决定：一列至少 18rem，最多 4 列，间距 0.75rem，都按根字号换算，宿主的字号设置让整张看板一起缩放。列宽随宽度连续变化，没有断点表，也没有行高。
- 每张卡片占一列，高度由组件自己上报：运行时量出文档内容的高度，经桥的 `height` 消息交给看板；组件在首次上报之前按列宽的 0.66 占位。上报的高度限制在列宽的 0.5 到 4 倍之间，越界按边界算。卡片对应的尺寸族是 `inline`（宽度是列宽，高度由组件上报）。
- 卡片的位置由 `model` 的纯函数算出：按阅读顺序逐张放进当前最矮的一列，同高时取靠前的那一列；同样的输入总是同样的结果。
- 卡片自己按宽度排版：iframe 的视口就是卡片的内容盒，组件用自己的媒体查询在窄宽度下换一套排版，不需要看板告诉它尺寸族。
- 卡片不换父节点：所有卡片都是看板里同一个容器的子节点，位置用绝对定位给出，宽度变化只改坐标，不重建 iframe。
- 整页只有一个 `ResizeObserver` 观察看板容器，也只有一个 `IntersectionObserver` 管离开视口的暂停。
- 卡片顺序就是实例在存储里的顺序。拖动重排、自由摆放与缩放都留到需要时另写 ADR；D2 为栅格交互选定的 gridstack 因此暂时没有使用者。
- 尺寸族继续写在 manifest 的 `sizes` 里，供会话内联、右侧栏与展开浮层使用；看板这一处只用 `inline`。声明的每个尺寸族都要在 `samples.json` 里有一份样例，尺寸矩阵按它渲染（D13）。

## 后果

- 同一屏里能放下高度不同的卡片，天气卡与番茄钟不必被拉成同一个高度。
- 列数随宽度连续变化，拖动窗口时卡片宽度平滑变化，没有断点处的跳变。
- 看板暂时没有拖动、重排与缩放；调整顺序要等后续实现。
- 组件必须让自己的根节点按宽度定高；把根节点撑满视口的写法在信息流里得不到高度。

## 重审条件

- 出现需要跨列的卡片时，列跨度的声明方式要重新决定。
- 需要自由摆放或拖动排序时，重新比较栅格库与自绘的位置模型。
