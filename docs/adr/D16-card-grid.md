# D16. 卡片盒子的自由布局

- **取代**：D15、D4

## 背景

D4 的固定断点栅格由 D15 改成信息流；D15 让卡片高度由组件上报的内容决定，位置按最矮列自动装箱。这样适合信息流，却把卡片尺寸交给了内容：用户不能把一张卡放大成两列、压矮成一行，也不能把它拖到另一张卡旁边。参考的组件形态是大小由容器给定的小组件：卡片先有一个盒子，组件在盒子里换排版。用户要的是可以拖动、可以缩放、内容跟着盒子走的看板。

## 决定

- 看板是一块列宽连续变化的栅格：列数按看板容器的宽度在一到四列之间判定，一列至少 18rem，间距 0.75rem，都按根字号换算。卡片不再参与列的装箱；每张卡有自己的盒子。
- 每张卡片存 `layout`：`x` 是列号，`w` 是跨列数，`y` 与 `h` 是根字号的倍数。新卡片放在最矮的一列底部，一列宽、22rem 高。列数变少时 `x` 与 `w` 按当前列数截断，`y` 保留；两张卡重叠时后放的一张往下推开，正在拖动的那一张先占住目标位置。
- 拖动改变 `x` 与 `y`，缩放改变 `w` 与 `h`。指针操作由卡片外壳的顶部把手与右下角手柄接收，拖动期间 iframe 不接收指针事件。卡片本身按指针的像素位移跟手，松手后的落点在格子里画成虚影；松手时才把位移吸附到列宽与 0.5rem 并提交整块布局。
- 松手时把整理过的整块布局提交给宿主，并带上布局修订号。宿主是唯一权威：布局修订号只在卡片增删与布局提交时加一，组件状态的写入不碰它，因此计时器正在更新状态时拖动不会变成过期；两个页面同时改布局时，后到的提交收到 409 与当前快照，页面按宿主的那一份重画（D5）。
- 卡片的 iframe 视口就是卡片的内容盒。组件按 `window.widget.size` 或媒体查询排版，填满盒子；组件上报的内容高度只给内联显示用，看板忽略它。组件在矮盒子里收掉次要信息，在窄盒子里换排版。
- 卡片不换父节点：所有卡片都是看板里同一个容器的子节点，位置用绝对定位给出，宽度与高度变化只改坐标与 iframe 视口，不重建 iframe。
- 整页只有一个 `ResizeObserver` 观察看板容器，也只有一个 `IntersectionObserver` 管离开视口的暂停。
- D2 原先为固定栅格选的 gridstack 在这里不用：卡片外层由 React 持有，iframe 不能换父节点，拖动与缩放的位移在 `model` 的纯函数里整理；卡片移动的过渡由外壳画，时长与曲线从令牌读（D10）。
- D5 里按断点保存的 `layouts` 表由本决策改成每张卡片自己的 `layout` 字段；D5 的宿主权威、单一写入者与修订号部分继续有效。
- 尺寸族继续写在 manifest 的 `sizes` 里，供会话内联、右侧栏与展开浮层使用；看板这一处把位置、像素盒与跨列数交给组件，`family` 是 `board`（D3）。manifest 可以用 `minBox` 声明自己缩到多小还排得下。

## 后果

- 组件必须在给定高度内排版；内容超出时由组件自己滚动或收掉次要信息，不能靠撑高卡片解决。
- 卡片之间可以留白，位置是用户的选择；看板不再追求把每一列填满。
- 列数变少时自定义的横向位置会被截断，恢复宽屏后卡片回到它存下的列；同一组卡片在窄屏上可能被推开，需要重新摆一次。
- 布局提交是一整块看板的原子写入，一次拖动只产生一次宿主往返。

## 重审条件

- 需要为每个列数分别保存布局时，把 `layout` 改成按列数索引的一份表，并重新决定切换列数时的迁移。
- 需要更细的横向位置（半列、像素）时，重新比较列单位与固定像素栅格。
- 内联与右侧栏也需要用户改尺寸时，把盒子的来源统一到同一份布局服务。
