# D19. 组卡：两张普通卡片共享一个盒子

- **状态**：原型

## 背景

翻转卡模板把一张卡的画面做成两面，两面来自同一个组件文档。看板上还有另一种需要：让两张已有的组件卡，例如一个数字与一张图表，在同一个盒子里翻面，正反两面各自保留自己的数据、状态与热重载。把两个组件塞进一个组件文档会跨过一张卡一个文档的边界；新增一个“组合组件”类型又要让两张卡分别更新，组件格式也会多一层。

## 决定

- 组卡由两张普通卡片组成，各自是普通的 `BoardInstance`，有各自的 `widget`、`hash`、`props`、`data`、`state` 与实例路由。两张卡多一个可选的 `group` 标记：`{ id, side, template }`，`side` 是 `front` 或 `back`，`template` 目前只有 `flip`。
- 组卡不是一个组件库类型。组没有自己的组件文档；外壳把两张画面放进同一个盒子，按模板决定哪一张在前。组卡的 id 只用来把两张卡认成一组，不占组件 id。
- 宿主提供 `POST /board/group` 与 `POST /board/group/remove`。加组时宿主一次写入两张卡片，共用一个 `layout` 与一个组 id；移除按组 id 一次删掉两张，不留下一半。两张卡的增删都让布局修订号加一，走与普通卡片相同的整块布局与修订号规则（D5、D16）。
- 原型阶段正反两面的组件固定为 `stat` 与 `chart`，正反两面都由调用方决定，界面暂时不做自由配置。组卡的添加与移除由浏览器半边的 `addGroup`、`removeGroup` 发起，宿主仍是唯一写入者。
- 组卡的 `layout` 是两张卡共用的盒子。布局提交、列数变化与整理都对两张卡写出同一个盒子；普通卡片的单画面路径不变。
- 组件库里有一行合成的“翻面组”入口：它不是组件目录，没有 manifest 与版本哈希，只影响添加入口。轻点加在末尾，拖到看板上时把落点作为两张卡共同的 `layout`；组本身仍不是组件库类型。
- 一张组卡只有一个卡片外壳、一个握手中心与一个 IntersectionObserver 的观察节点。外壳里放两层 `CardSurface`，正反两个组件文档各自握手、各自有端口；翻面只转外壳的内层，两个 iframe 都留在 DOM 里，藏起来的一面经端口暂停。
- 翻面由指针决定：指针进入组卡转背面，离开转正面。藏起来的一面经端口暂停；组卡离开视口时两面都暂停。减弱动效下仍然换面，外壳不做过渡。

## 后果

- 快照与工具看到的是两张卡片，组卡只多一层 `group` 标记。按实例计数的界面要把同一组的两次出现认成一个盒子；移除与拖动都要按组处理。
- 两张卡各自存状态与数据，正反两面可以来自不同的数据源；热重载只换其中一张时，组卡的另一面照常显示。
- 原型只支持固定的正反组合与翻转模板；组件库里的一行是合成的添加入口，组本身没有 manifest，两面还不能自由配置。
- 组卡的两条实例记录必须在布局写入时保持同一个盒子；一次只改一张的旧工具会把组拆开。
- 悬停翻面没有触屏与键盘的等价入口。指针在 iframe 上方时父文档收不到悬停，组卡用一层透明的接指针面接住它；组里组件的指针交互暂时被这层面盖住。

## 重审条件

- 组卡成为真正的组件库类型、或允许用户挑选正反两面时，重新决定组的 manifest、添加界面与组的 props。
- 组卡要出现在会话内联、右侧栏或展开浮层时，决定组在一张卡片之外怎么表示。
- 组卡的布局改成一条组记录而不是两条实例记录时，重新审视快照形状与旧看板的迁移。
- 需要触屏与键盘也能翻面时，增加点击与按键入口，重新决定指针移出后是否翻回。
