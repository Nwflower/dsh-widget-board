# D21. 多块看板

## 背景

D5 的存储是一份 `$DSH_HOME/widget-board/board.json`：一块看板、一页卡片。用户要在同一处放几页内容——工作、阅读、试验各一块——并像切换标签那样在它们之间来回；每块看板有自己的卡片、盒子与修订号。D5 的重审条件已经写下这条路：「出现多块看板时，把文件拆成每块看板一份并在启动时按需读入」。标签切换的那枚滑动药丸来自视觉参考里的 tabs-sliding（D10 的令牌与套件里已有同类原语）。

同时要定的是切换时组件怎么办：同时挂载看不见的看板，切换时组件不用重挂，但 iframe、计时与动画的成本随看板数叠加；只挂当前看板，成本收在一块看板内，切回来时组件重新挂载。

## 决定

- 存储拆成两份：`boards.json` 是索引（格式版本、标签次序、当前选中），`boards/<id>.json` 是每块看板自己的一份，形状仍是 D5 的 `Board`（格式版本 2），标题只写在看板里，索引不复制一遍。旧版本的单份 `board.json` 在第一次打开时搬成第一块看板，搬完才删掉原文件（D5 的原子写入与版本报错照旧）。写入按块串行、先写临时文件再改名；索引只在新建、移除与切换选中时写。
- 路由按对象分：动作的对象是一块看板时看板 id 写在路径里（`POST /boards/<id>/layout|instance|group|rename|remove|activate`）；对象是一张卡或一组卡片时按它们自己的 id 找——卡片与组的 id 全工作区唯一，这几条路由因此不带看板（`/instance/<id>/…`、`/group/remove`）。`GET /boards` 一次回全部看板与当前选中，`POST /boards` 新建一块。
- 事件按改动分：布局事件带看板 id；卡片状态与数据事件只带卡片 id；换选中推一条 `active` 事件，页面换标签而不重取快照；卡片或看板增删仍让页面重取整个工作区（D18）。
- 界面：看板页顶部一条标签，每块看板一个标签加一个新建入口，活动标签有一枚滑动的药丸（时长与曲线读令牌，减弱动效时不走过渡）。一块标签是一组：文字按钮负责切换，右边一枚更多按钮，悬停或组内任一控件拿到焦点时出现，键盘聚焦时始终可见；更多按钮与标签右键打开同一张管理菜单，菜单记着目标看板 id，从别的标签打开不切换看板（B1）。菜单里只有改名与删除，两者的标题规则、计数与写请求收在 `packages/client/src/board-management/`；设置页那一节列出全部看板，调同一份动作。设置页那一节与卡片右上角的设置按钮画在不同表面上，各自用一个类名前缀：宿主把插件样式拼进同一张样式表、设置节又排在后面覆盖同名规则，共用前缀会让卡片按钮的定位与尺寸套在设置面板上。
- 只挂当前看板：切换标签时旧的卡片卸载、新的重新挂载，iframe 数等于这一块看板的卡片数。组件在切回来时重新初始化，计时、动画与没有写进宿主的本地状态从头开始；界面状态与数据由宿主上的那一份恢复。离开视口仍暂停，组件经 `window.widget.onPause` 停掉计时器（D16、D23）。每块看板自己的修订号仍各算各的，过期的判定与整块提交不变（D5、D16）。
- 一块看板是一块看板：整块布局的原子提交、整理的阅读顺序、拖动与缩放的本地预览都只作用于选中的那一块。

## 后果

- 只挂当前看板把内存与首屏成本收在一块看板内；切换标签会重挂组件，计时、动画与没有写进宿主的本地状态重来，切回时可能看到一次重载。暂停只再需要处理视口与翻面组藏起来的那一面。
- 一块看板一份文件让每次状态写入只碰它自己那一份，D5 里「每次写入都要写整份文件」的代价随看板数不再叠加。
- 管理动作与它作用的标签在同一个视野里，改名与删除不必先离开看板；设置页那一节仍是「一次看全所有看板与各自张数」的入口。标签条为每块标签多留一枚按钮的宽度，悬停出现时不把相邻标签推开。
- 切换标签要写一次索引并推一条事件；两个窗口同时切换时后到的那一次为准（D5 的单一写入者）。

## 重审条件

- 切换重挂造成可见的卡顿、滚动位置或未持久化状态丢失时，考虑保留最近访问的几块看板，或把需要保留的状态写进宿主。
- 看板多到标签条放不下时，决定折叠、横向滚动还是分组。
- 需要每块看板自己的布局服务（会话内联、右侧栏也改尺寸）时，把盒子的来源统一到同一份布局服务（D16 的重审条件）。
