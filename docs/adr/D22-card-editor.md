# D22. 卡片设置弹窗与组槽选择

## 背景

卡片的 `props`、数据源与授权此前只有 agent 能改：会话里的工具能写，人只能在卡片上看。一个需要 API key 的卡片没有地方放密钥；一个组卡的两个槽固定为 `stat` 与 `chart`，人不能换。把密钥塞进 `props` 或 `state` 会进入看板文件、导出包与工具结果，不能作为凭据的存放处。宿主已经提供 `ctx.credentials` 这条凭据接缝：值按操作解析，配置面只看得到 `configured/source/writable`。

## 决定

- 卡片设置做成一块弹窗，由看板页持有，按看板页的矩形定位；它只盖住看板内容，不盖宿主侧栏（D1）。弹窗不是原生 `<dialog>`，因为顶层会越过插槽的表面。
- 弹窗分「组件设置 / 凭据 / 数据与权限 / 关于」四节。单卡直接打开这四节；组卡在四节之上多一条槽条，每个槽仍是一张普通卡片实例（D19）。
- `widget.json` 增加 `credentials`：`ref`、双语 `label`、可选 `description` 与 `required`。`ref` 按环境变量名校验。组件的 props 表单字段标签从 `text` 的 `props.<key>.label` 与 `props.<key>.hint` 取，没有时退回 schema 的 title 或字段名。
- 设置弹窗读一份单独的 `CardSettings`：实例、组件声明、props schema、数据源与权限、当前授权、凭据状态。它不塞进每次工作区快照。
- props 由 schema 生成表单：字符串、数字、布尔与字符串枚举直接出控件，对象、数组与其他写法切到整份 JSON 编辑；宿主用 Ajv 按 manifest 的 props schema 校验，逐字段回错误。`widget_place` 改 props 也走同一条校验。
- 凭据写入只从人的界面发起：`POST /instance/<id>/credential` 只接受 manifest 声明过的 `ref`，走 `ctx.credentials` 的 `set`/`unset`，响应只回状态。不注册 agent 工具，卡片代码永远拿不到值。宿主的凭据服务缺席时界面给出可见的说法（D11）。
- 数据与权限一节显示数据源、提供方、它登记的主机与命令、当前组件版本上的授权，并提供「允许 / 撤销」与「立即刷新」。授权仍只由人给出（D6）。
- 组卡的槽条可以把一个槽换成组件库里的另一个组件：`POST /group/<id>/slot` 只改选中的那条实例，重置它的 props、data、state 与数据源，另一个槽不动；组卡共享的盒子按两个槽当前组件的最小盒子取最大值。添加翻面组之后直接打开槽条。
- props 的变化走 `instance` 事件带上 `props`，页面就地合并；组卡换槽发一条 `board` 事件，页面重取整份快照。
- 弹窗一次只开一块；关闭有未保存的 props 草稿时先确认。卡片或组被移除、或切到另一块看板时弹窗关掉。

## 后果

- 组件的可配置面由 manifest 决定，内置、用户与插件组件走同一份表单；组件作者不再需要为每一种 props 写设置界面。
- 密钥不进入看板文件、导出包与工具结果，但本机凭据文件对同一个操作系统用户可读，agent 的工具进程也是这个用户；这层不是对 agent 的操作系统隔离。
- 凭据服务的缺席与只读来源（启动环境或 `.env`）在弹窗里有不同说法，写入按钮相应禁用。
- 组卡仍固定两个槽；槽条按列表画，两个以上的槽要先把 `group.side` 扩成 `slot` 与模板。
- 设置读模型与 props 校验多出三条实例路由与一条组路由；`routes.ts` 只保留挂载，三条设置路由住在 `settings.ts`，换槽住在 `groups.ts`。

## 重审条件

- 组卡支持两个以上的槽或模板选择时，重新决定组的槽模型、槽条的布局与组的最小盒子。
- 同一个组件需要按卡保存不同的凭据值时，改用 `ctx.credentials` 的记录（以卡片 id 为键），而不是现在的共享 `ref`。
- agent 也要能换组槽时，决定扩 `widget_place` 还是加一个新工具；凭据写入仍然只留给人的界面。
- 设置项超出 props 与凭据（例如版本固定、刷新间隔覆盖）时，重新决定 manifest 的字段与读模型。
