# D27. 卡片设置弹窗：配置、日志与关于

- **取代**：D22

## 背景

D22 把弹窗分成四节，props 由 schema 生成表单。用了一段时间之后有三处不对：表单按 schema 把字段全铺出来，卡片上真正写过的往往只有标题与一两个字段，空着的控件占了大半屏；真正需要改的是「地点」「时区」「列数」这类影响行为的项，而「卡片标题」这种只换一行字的占位占着同样的位置。元数据与凭据分成两节，读的人要先判断「这算配置还是算密钥」，其实两样都是这张卡的配置。组件对外请求没有地方看，出了问题只能翻控制台。

## 决定

- 弹窗仍是看板页持有的一块浮层，按看板页的矩形定位，只盖看板内容，不盖宿主侧栏（D1）。
- 三节，次序固定：配置、日志、关于。单卡直接打开这三节，默认停在配置；组卡在之上多一条槽条，每个槽仍是一张普通卡片实例（D19）。
- 配置一节是一张两列的表：左边是这一项的名字与说明，右边是控件。值来自 manifest 的 `props` schema：字符串、数值、布尔与字符串枚举各出对应的控件，对象与数组只说明要用 JSON 工具写。一个「保存」把这一节里改过的字段与填了值的凭据一起交上去。字符串字段可以用 `format` 收紧成城市名：`format: "city"` 的右边是可检索的选择器——边输入边从城市检索里列候选（名字、地区、国家），点一条就把名字、双语地名与坐标按 `fills` 写进 props，行下显示解析出的坐标；旁边一枚「定位」用当前位置填，保存时仍会核对一遍；`format: "hidden"` 的字段不出控件，留给这类派生值。候选查询在输入停下约 0.3 秒后发出，按输入的语言选中文或英文索引，同一个前缀只查一次；解析由浏览器半边问固定的城市检索、反向地名与网络出口位置服务；它不是卡片的数据源，不进卡片的请求日志。
- 组件声明的凭据与普通字段排在同一张表里，差别只在右边那一列：一枚状态牌（已配置、未配置、只由启动环境提供）与一个密码框。值只往宿主的凭据服务走，界面上与返回值里都没有它；组件自己读不到。
- 组件只声明用得上的字段。内置组件里的「标题」「眉题」「右侧说明」这类只换一行字的占位不再声明，也不再出现在配置里；字段的中英文名字写在 manifest 的 `text.props.<key>.label` 与 `.hint`，枚举值的显示名写在 `text.props.<key>.<value>`，缺的按原值显示。
- 日志一节列出这张卡对外的每一次请求：方法、主机与路径、状态、耗时，最新的在最上面。日志活在宿主进程里，按卡留最近几十条，不写盘；凭据不进日志。
- 关于一节放组件的身份（来源、提供方、版本、hash、刷新策略）、卡片绑定的数据源、声明的宿主能力、它们的权限范围与授权状态，并提供「允许 / 撤销」与「立即刷新」。授权仍只由人给出（D6）。
- 宿主代发请求的形状（D28）：`request` 里写 `url`、`method`、`headers`、`body` 与 `auth`；`auth` 写 `{ credential, scheme }`，由宿主把值拼进请求头。插件只提供这条通道，不为每一个外部接口写一段能力代码。
- 弹窗的样子是一张浮在背板上的卡片：题头带一层极淡的主色，三节标签是一排分段按钮，正文里每一节是一张自己的卡，页脚一层自己的底。颜色读宿主的 `--dsw-*` 别名，间距、字号、圆角、时长与曲线读看板令牌（D10）。
- 设置读模型 `CardSettings` 不变：实例、组件声明、props schema、数据源与权限、当前授权、凭据状态；它不塞进每次工作区快照。日志走单独的一条只读路由。
- 组卡的槽条可以把一个槽换成组件库里的另一个组件：`POST /group/<id>/slot` 只改选中的那条实例，重置它的 props、data、state 与数据源，另一个槽不动；组卡共享的盒子按两个槽当前组件的最小盒子取最大值。
- props 的变化走 `instance` 事件带上 `props`，页面就地合并；组卡换槽发一条 `board` 事件，页面重取整份快照。

## 后果

- 组件的可配置面仍由 manifest 决定，内置、用户与插件组件走同一条路；组件作者不再需要为每一种 props 写设置界面，但要把字段的名字与说明写上，否则界面只能退回字段名。
- 内置组件的标题固定成组件自己写的那一行，用户不能再从配置里改；要改就得在 manifest 里重新声明一个字段。
- 密钥不进入看板文件、导出包、工具结果与日志，但本机凭据文件对同一个操作系统用户可读，agent 的工具进程也是这个用户；这层不是对 agent 的操作系统隔离。
- 只读来源（启动环境或 `.env`）在配置里写明，写入按钮相应禁用。
- 城市名的解析依赖 Open-Meteo 的城市检索、BigDataCloud 的反向地名与 ipinfo.io / freeipapi.com 的网络出口位置；这几个地址写死在插件里，不可达时「定位」在弹窗里给出原因，手写的城市名也保存不了。
- 组卡仍固定两个槽；槽条按列表画，两个以上的槽要先把 `group.side` 扩成 `slot` 与模板。
- 读模型与路由多出一条只读的日志路由，住在 `settings.ts` 里；组路由仍在 `groups.ts`。

## 重审条件

- 组卡支持两个以上的槽或模板选择时，重新决定组的槽模型、槽条的布局与组的最小盒子。
- 同一个组件需要按卡保存不同的凭据值时，改用 `ctx.credentials` 的记录（以卡片 id 为键），而不是现在的共享 `ref`。
- agent 也要能换组槽时，决定扩 `widget_place` 还是加一个新工具；凭据写入仍然只留给人的界面。
- 设置项超出 props 与凭据（例如版本固定、刷新间隔覆盖）时，重新决定 manifest 的字段与读模型。
- 组件要读回自己的凭据时，先决定信任边界：能让组件看到值，就等于把它交给写组件的人，日志与快照都要跟着改。
- 日志要长期留存或跨重启保留时，重新决定它落在哪里，以及谁可以清掉。
- 城市字段要支持别的解析服务、或要把解析搬到宿主侧（例如需要审计与日志）时，重新决定它住在设置界面还是宿主。
