# D29. 落在浏览器里的能力与整页转场

## 背景

宿主能力（D24）沿 `/instance/<id>/call` 到宿主进程，由提供方读那里已有的服务。外观主题住在浏览器：`ctx.theme` 的当前偏好、解析出的浅色或深色、以及 `theme/change` 都只在页面上；宿主要改它，只能写 `ui-theme` 设置，再由浏览器跟随。若把主题能力只做成宿主能力，组件按下开关后要等一次设置写入与一次推送，而且没有任何一处能在整页上把切换包进一次过渡。

组件还带着一个位置信息：按下的那一点在卡片里的坐标。父页面知道 iframe 在视口里的位置，能把两者合成整页坐标；这件事只有浏览器半边做得到。

## 决定

- 浏览器半边也有一张能力表：按能力名登记，卡片收到 `call` 时先问这张表，接得住就本地执行，接不住再走宿主路由（D24）。表是通用机制，不按组件或能力名分支；登记项随插件生命周期撤下。
- 组件 manifest 的 `capabilities` 同时进工作区快照（`WidgetSummary`）。本地执行也要先核对声明，预览与一次性快照里的调用直接拒绝，与宿主路由的判据一致（D6）。
- 外观主题是一项通用能力 `dsh.theme`：参数是目标偏好（`light`、`dark`、`system`）与可选的转场圆心，结果是落定的偏好与解析出的配色。任何组件都能声明与调用，不是开关灯组件的专用接口。宿主半边注册同一项能力作为兜底：读 `ui-theme` 设置里的 `preference`，带修订号写入，冲突时重读一次；浏览器半边缺席时主题仍然能改。
- 浏览器侧实现用 `ctx.theme.setTheme` 写偏好，并把这次写入包进 `document.startViewTransition`：旧快照原地不动，新快照从组件报来的圆心以 `clip-path: circle()` 展开。圆心换算、半径与时长由父页面算；时长读令牌的 `theme-circle`。浏览器不支持 View Transitions、系统要求减弱动效、或上一次转场还没收尾时，直接切换，不做整页动画。
- 圆心与半径写成百分比，不写像素：新快照层按设备像素缩放，像素值在 1.5 倍屏上会被再缩小一次，圆心落到左上方。百分比相对快照自己的参考框解析，换像素密度仍落在同一个视觉点；圆半径的百分比按参考框的对角线归一化，视觉大小同样不随密度变。
- 旧快照拍完之后才暂停其它卡片的逐帧绘制：暂停放在 View Transition 的更新回调里，按下的一刻画面不变；天气这类卡片在转场期间不再画后面的帧，转场结束再按卡片分批恢复。卡片自己的圆环等到主题令牌真正落地时才放，跟整页的圆心取同一个点、同一个时刻。
- 转场只在根节点上挂一个标记与几个自定义属性，动画结束就摘掉；不覆盖宿主自己的 View Transition 规则。

## 后果

- 主题切换在按下的一刻就发生，不必等宿主往返；宿主兜底仍可用于原生组件、旧页面或别的宿主。
- 浏览器侧能力绕开了宿主的授权与 schema 校验，所以声明检查、预览拒绝与错误原样回传都要在本地再写一遍。需要授权的能力不应放进这张表。
- 整页转场的开销是两张视口快照；同一时刻只跑一次。快照会把视口里的每张卡片拍进去，卡片越多、像素密度越高，拍快照的那一下越重；桌面壳上量到的是拍快照与两层快照合成，而不是 `clip-path` 每帧重排。
- 暂停放在旧快照之后，旧画面保持按下时的样子；新快照拍下暂停后的稳定画面，转场结束时两边对得上。
- 暂停卡片只停绘制，不减少快照要拍的沙箱画面；要彻底去掉这笔开销，只能放弃整页快照，也就是放弃圆外的旧画面。
- 新增一项落在浏览器的能力不需要改桥或路由；但浏览器侧实现与宿主侧声明要成对维护，缺一边时要么落到宿主兜底，要么在设置弹窗里显示不可用。

## 重审条件

- 宿主自己提供页面级转场入口时，去掉这里的圆心换算与快照包装，只留能力调用。
- 出现需要流式、订阅或长时间运行在浏览器的能力时，重新决定本地能力的取消与背压。
- 第三方插件也需要登记浏览器侧能力时，把这张表升级成经 `widgetBoard` 服务发布的公开面，并补版本协商。
