# D30. 组件市场：索引、分发、信任与接入点

## 背景

组件能以 `.dshw` 导出导入（D8），但没有发现、版本、更新与作者归属；两个作者不能都发布 `weather`。issue #3 与 #4 要求给出组件市场的索引格式、分发方式与信任模型，并给插件留一个市场接入点：看板核心不认识任何市场实现，市场插件卸载后已安装的组件照常可用。

宿主已经有一个插件市场（`@deepseek-ai/dsh-plugin-market-index`），它安装的是插件包，通过 npm 或 git 拉取。组件市场交付的是 `.dshw` 目录包，安装走看板自己的写入路径。两者的共同形态是「静态索引 + 版本化条目」，安装与信任的位置不同。

仓库已有 GitHub Pages 部署（`.github/workflows/pages.yml`），市场原型挂在同一站点的 `market/` 子路径下，不新建服务。

## 决定

- 市场索引是一个静态 JSON（格式 1），放在 Pages 的稳定地址；`.dshw` 包放 GitHub Releases：发布资源不可变，按哈希引用。索引按 Ajv 与 JSON Schema 校验，不合格时市场区显示原因，不加载半个市场。
- 索引的形状写在 `packages/contracts/market-index.schema.json`：`format`、`market`（标题、说明、`updatedAt`）与 `widgets`；每个条目是 `id`（带作者域）、标题、说明、作者、仓库、许可证、标签与全部版本；每个版本是 `version`、`package`（地址、sha256、字节数）、`sizes`、`requires`（看板服务版本与 DSH 版本）、`declares`（能力、凭据与主机）、`changelog` 与 `publishedAt`。字段只增不减，删除字段要按组件格式的迁移规则走（D7）。
- 原型挂在同一个 Pages 站点的 `market/` 子路径下：`index.json`、原生 HTML 的浏览页与两个示例包。`npm run market` 从仓库里的组件目录重新打包（把 manifest 的 id 与版本换成市场条目声明的）并改写索引；`node scripts/market.mjs --check` 核对索引与包（sha256、字节数、包内 id 与版本、sizes、declares），在 `npm run verify` 与 Pages 部署前各跑一次。
- 市场条目的 id 必须带作者域，形如 `<作者域>.<名字>`；扁平 id 属于本地组件，继续有效。**已实现**：`WIDGET_ID_PATTERN` 接受两种形式，`readWidget` 只允许 `market` 来源使用带作者域的 id，本地来源用它会在读取时被拒绝并说明原因。
- 看板发布服务 `registerMarketProvider`，市场插件实现 `list()` 与 `fetch(listing, version)`，条目形状是 `MarketListing`（标题、作者、许可证、版本、尺寸族、依赖声明、包地址与 sha256、大小）。看板负责：逐条校验、超时（15 秒）、条数上限（256）、市场区界面、安装、来源记录与冲突处理。提供方不接触文件系统与看板存储。
- 安装路径只有一条：`POST /library/market/install`，请求体 `{ provider, id, version, replace? }`。顺序是：按提供方解析条目 → `fetch` 取包 → 核对大小与 sha256 → 用 `unpackWidget` 解包并校验 → 包内 manifest 的 id 与条目一致 → 索引的 `declares` 是包内声明的子集 → 检查 id 冲突 → 写进 `$DSH_HOME/widget-board/market-widgets/<id>/` → 记一条来源（`sources.json`：提供方、条目、版本、sha256、安装时间）→ 重读组件库。
- 来源顺序是 `builtin` → `user` → `market` → `plugin` → `example`，同 id 先到者胜。插件在运行时才注册目录，来源表按这份次序插入，不按注册先后追加。
- 冲突处理：内置、用户、插件与示例来源已经有这个 id 时拒绝安装（409，`widget-conflict`，带上两边的哈希）；市场来源里同 id 不同内容时，要显式的 `replace=true` 才覆盖，覆盖前旧目录整个清掉（D7 的版本就是整个目录）。
- 提供方失败只影响市场区：`list` 失败或超时记在它自己那一节，安装失败的原因回到组件库面板，其余提供方与其余两个区不受影响。提供方撤下后条目从快照消失，已安装的组件保留在 `market` 来源里。
- 市场条目随快照走（`WorkspaceSnapshot.market`），界面按提供方分节渲染标题、作者、许可证、版本与声明；没有提供方时画固定的空状态。
- 信任边界与 D8 一致：安装前给人看作者、许可证、版本、声明的能力、凭据与主机权限、包哈希；索引被篡改时包哈希与安装确认页是最后一道检查。作者身份只靠索引来源与仓库地址，不引入签名。

## 后果

- 市场是可选的：没有市场插件时，组件库照常使用，市场区显示空状态。
- 索引与包的格式成为公开契约；字段只增不减，删除字段要按组件格式的迁移规则走（D7）。
- `sources.json` 只记最近一次安装，不保留历史版本；回退与更新检查要在它旁边另加记录。
- 安装的可信度取决于索引的托管方；Pages 站点被替换时，包哈希只能挡住内容被换，挡不住索引整体指向另一份内容。
- 原型的包与索引一起提交在仓库里：改组件源码之后要跑 `npm run market` 才会更新包，`--check` 会指出不一致，但不知道源码改了。

## 原型没有决定的事项

- 市场浏览页的搜索、评分、评论与举报：需要服务端。
- 多市场之间的去重与合并：现在每个提供方一节，条目按提供方各自的 id 并存。
- 更新提示与回退：`sources.json` 里没有版本历史，市场区只显示「已安装」。
- 包与索引的签名、作者身份验证。
- 索引分页与远端搜索：当前 `list()` 一次返回全部条目，上限 256 条。

## 重审条件

- 出现第二个市场提供方、或需要跨市场去重时，重新决定条目 id 的唯一性规则与来源合并方式。
- 需要更新提示与回退时，把版本历史写进 `sources.json` 的旁边，并给市场区加「可更新」的判定。
- 需要作者身份时，加入签名与发布者验证，取代「索引来源即身份」的当前做法。
