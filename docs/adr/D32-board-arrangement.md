# D32. 看板的两种排列偏好：自由位置与整齐行列

## 背景

D16 把看板做成自由布局：每张卡有自己的盒子，位置与尺寸都由用户拖出来。自由布局适合拼贴，但卡片底部参差、手动对齐成本高；「整理」也只能消掉空隙，不能让同一排的卡片等高。需要另一种排法：卡片按保存的顺序逐行铺开，同一排等高，行列间距一致；已经用自由布局摆好的看板不该被升级改变。

## 决定

- 一块看板多一个可选的 `arrangement` 字段：`mode` 是 `free` 或 `aligned`，`aligned` 保存排列顺序与每个排列单元的期望宽高，切回自由模式后保留这份偏好供下次恢复。排列单元是普通实例或一整组翻面卡（取正面实例的 id，D19）。看板磁盘格式从版本 2 升到版本 3；旧看板读成 `free`，原实例 `layout` 不动，新建与第一次启动的看板是 `aligned`。
- 两种模式共用同一批卡片实例、内容与状态，不复制卡片。实例的 `layout` 继续保存自由坐标；整齐模式的像素坐标是每次渲染时由顺序与期望宽高派生的，不写进磁盘。窗口宽度与根字号变化时派生结果跟着变，存下的偏好不用重写。
- 整齐模式由 `model` 的纯函数排版：期望宽度收进当前列数并满足组件最小盒子，按顺序逐行装入，一行内所有格子的 top 与 height 相同，行高是这一行期望高度的最大合法高度档，纵向不经过自由布局的 2rem 吸附，后排不回填前排空位。
- 排列偏好用与布局提交同一条并发规则（D5、D16）：一次提交带期望的布局修订号，宿主核对后原子写入并递增，过期返回 409 与当前快照。模式切换、顺序调整与整行缩放都走这一条提交；自由布局的提交路由在整齐模式下来到时同样以 409 与快照拒绝，避免两种客户端互相覆盖。
- 手势按模式分开：自由模式下拖动改坐标、缩放改盒子（D16 不变）；整齐模式下拖动是调整顺序——按指针落入的派生格子确定插入位置，松手只提交新的顺序——缩放横向改自己的期望宽度、纵向把整行的期望高度抬到同一档。卡片不换父节点，iframe 不重挂（D16）。
- 卡片与组的增删同步维护排列偏好：加入的单元接在顺序末尾，移除的单元连同它的期望宽高一起离开，不留悬空引用。看板包交换沿旧格式携带实例的 `layout`；导入目标看板是整齐模式时按包内顺序重建排列顺序。
- 「整理」仍是自由模式下的显式动作（D16）；整齐模式本身已按行排列，没有对应的整理动作，两个控件分开命名。

## 后果

- 看板数据多一种形状：版本 3 的文件里 `arrangement` 缺失或不合法属于损坏数据，读取时报错并保留原文件，不替用户重建顺序。
- 整齐模式的显示宽度受当前列数限制，窄屏下跨列期望会被截断；恢复宽屏后期望宽度原样生效，不需要用户重新摆。
- 组卡的期望宽高是整组共享的一个盒子；正反两面的最小盒子取并集（D19）。
- 客户端要同时持有两种渲染路径与两套手势；同一块看板切换模式时提交一份偏好即可，卡片文档不重载。

## 重审条件

- 需要第三种排法（例如瀑布流或固定行数分栏）时，把 `arrangement` 扩成带判别字的联合，重新决定迁移与手势。
- 整齐模式需要卡内隐藏、跨行拖动或行内换位动画时，重新决定派生结果与手势草稿的关系。
- 看板包要携带独立的排列元数据（format2）时，重新决定包格式与旧包的兼容范围。
