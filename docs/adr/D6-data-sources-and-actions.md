# D6. 数据源、动作与授权

## 背景

组件在沙箱里拿不到网络与本机（D3），但它要显示的东西来自各处：agent 推送的结果、其他插件的状态、本机命令的输出、网上的接口。参考截图里有一张「点一下就运行本机 Python」的卡片。组件还需要反过来影响外界：刷新、运行、把内容交给一个会话。这些能力有的危险，必须由人批准。

注册表最初只有名字，没有归属，也没有「谁允许的」这一层：组件在 manifest 里声明过一个动作名，宿主就照着名字执行，而组件代码——内置的、用户目录里的、以后 agent 写出来的——都是不可信的。装上第一个真实提供方之后，一段组件代码只要声明与插件动作同名的 id，就能让那个插件替它动手。

## 决定

- 数据源是宿主上的注册表，一个实例的 `source` 指定它的数据从哪来：
  - `static`：固定数据。
  - `push`：agent 用 `widget_push` 推送。
  - `service:<name>`：读其他插件发布的 cordis 服务，例如任务看板的 `taskBoard`。
  - `program`：经 `ctx.ptcRuntime` 在沙箱策略下运行的程序。
  - `command`：经 `ctx.subprocess` 运行的本机命令。
  - `http`：宿主代为请求，只访问 manifest 声明并经批准的主机。
- 数据源与动作的注册带上 `provider`（提供方的包名），名字在同一时刻全局唯一；跨提供方重名时后到的注册抛出并说明原因，不静默覆盖。组件在 manifest 的 `actions` 里用 `提供方:名字` 点名其中一个；裸名字按全局唯一解。
- 数据源的结果先按 manifest 里 `data` 的 JSON Schema 校验，不合格的结果不写入，卡片显示故障（D11）。
- 动作在 manifest 里声明，未声明的动作一律拒绝。宿主统一分派：`refresh`、`run`、`prompt`（把内容交给一个会话）、`openSession`、`setState`；其他插件可以经服务注册新的动作（D12）。
- 需要授权的能力：`command`、`program` 的非只读策略、`prompt`、网络主机。数据源与动作各自在自己的注册里声明 `permission`（`hosts` 与 `commands`）；没有声明权限的不必问人——它们只读宿主自己的东西（读一个插件发布的服务、看板自己的状态）。
- 授权只由人在界面上给出，按组件的内容哈希记入 `$DSH_HOME/widget-board/grants.json`。组件更新后哈希就变了，之前给出的授权不再匹配，要重新确认；提供方换掉实现、把动作要的权限改大之后同样要重新问。工具不提供授权的能力：能由 agent 盖章的授权形同虚设（与任务看板「高于基线的权限只能人工确认」同理）。
- 接口：`POST /instance/<id>/grant` 与 `POST /instance/<id>/revoke` 由人经界面调用；`POST /instance/<id>/read` 按卡片绑定的数据源读一次。缺授权时动作与读数据都回 **403**，响应体里带 `code: "grant-required"`、`kind`、`id`、`provider` 与要问的权限；卡片据此就地画出「允许」按钮。看板自己提供的数据源（`dsh-widget-board`）不经过授权——它不是第三方代码。
- `ctx.approval.request` 绑定发起调用的会话 agent。agent 经工具触发需要授权的动作或导入时，在已授权之外，这一次调用再经它向会话询问；看板界面上用户点击发起的动作没有 agent，由已有的授权放行。
- 刷新策略在 manifest 里声明（D7）：按需、或按一个间隔。宿主上只有**一条**定时链：它按「有哪些卡片声明了定时刷新」与「现在有几个看板页在看」算出要不要跑、跑多快，每次只读到期的那几张卡；没有观众时一律不跑（D5）。声明了按需的卡片从不被定时读。定时读与手动读、工具读走同一条路径，因此授权检查也只有一处。

## 后果

- 组件作者写的是「数据长什么样」与「需要哪个数据源」，取数的代码在宿主一侧，组件本身只管显示。
- 每加一种数据源都要回答它的授权规则与失败形态。
- 一个需要授权的组件在用户确认之前只显示「等待授权」，agent 无法替用户跳过这一步。
- 组件改一个字符（哪怕只是样式）就会让已有授权失效，用户要再点一次。这是内容寻址的代价，也是它的意义。
- 没有观众的实例不刷新，数据可能在用户打开看板时才更新；需要后台保持新鲜的组件要在刷新策略里声明。
- 数据源与动作的名字空间是扁平的，重名靠拒绝而不是覆盖；提供方多了之后可能需要在界面上把 `提供方:名字` 写全。

## 重审条件

- 宿主提供插件可用的定时任务服务、且能按观众停启时，调度改为接入宿主的。
- 出现按会话或按来源的信任分级（例如「我自己写的组件默认放行」）时，重新决定授权的粒度与默认值。
- 授权表长到影响快照大小时，把快照里的授权改成按需查询。
