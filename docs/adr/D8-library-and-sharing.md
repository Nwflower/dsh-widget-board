# D8. 分享、导入与组件库

## 背景

一开始没有组件市场，组件仍然要能在人与人、机器与机器之间流转，用户也要能管理自己手上的组件：知道它从哪来、用在哪、能不能更新、怎么回退。以后接入市场时，不希望再改一遍格式与流程。

## 决定

- 只有一种组件交换格式：`.dshw`，组件目录原样打成 zip，读写用 fflate。解包前校验：路径不越出组件目录、扩展名在白名单内（html、css、js、json、svg、png、webp、woff2、md、txt）、总大小与文件数不超过上限。
- 看板交换格式 `.dshboard`：看板标题、每张卡片的盒子与 props，以及用到的全部组件（按哈希内嵌）。实例的 `data` 与 `state` 默认不导出，勾选后才带上。
- 每个组件记一条来源：`local`（用户在目录里自建）、`agent`（会话生成）、`file`、`url`（直链或 git 仓库里的目录，记住地址以便检查更新）、`plugin`（随提供它的插件安装与卸载，D17）。
- id 是 `<作者域>.<名字>`。本地与 agent 生成的组件作者域是 `local`，导入的组件沿用 manifest 的 `author`。同 id 不同内容的导入先显示差异，由用户选择替换、另存为新 id 或取消。
- 导入时显示权限确认页，同时跑一遍尺寸矩阵自检，报告与预览放在同一页；授权由人在这一页给出，按哈希记录（D6）。
- 编辑一个导入来的组件时，自动复制成 `local.<名字>` 副本并记下 `forkedFrom`；上游有新版本时提示「你的副本已修改」，差异可以交给 agent 合并。
- 组件库是看板插件里的一个页面，按来源分组（内置、我的、导入、插件）。每个组件：各尺寸族预览、权限、版本历史、被哪些看板使用；动作：复制为我的、导出、检查更新、回退到历史版本、删除。删除时列出仍在使用它的实例，由用户选择一起移除或取消。blob 由显式的「清理」删除，清理只删除会话日志与存储里都没有引用的 blob。
- agent 的入口是 `widget_library` 工具：`export`、`import`、`fork`、`rollback`、`delete`、`check-update`；`import` 经 `ctx.approval.request` 向会话询问，导入后的组件在用户于确认页授权之前不运行任何需要授权的能力（D6、D9）。
- 市场以后只是又一种来源：一份列出组件地址与哈希的索引，导入走同一条校验、批准、存储的路径。

## 后果

- 没有市场时，git 仓库加 `url` 来源就能订阅别人的组件。
- 文件里只有哈希清单，没有签名；完整性可以校验，作者身份无法校验，信任靠权限确认页与沙箱。
- 清理 blob 要扫描会话日志，代价随会话数增长，所以只在用户触发时运行。

## 重审条件

- 接入市场或出现需要确认作者身份的分享场景时，加入签名与发布者身份。
