# D8. 分享、导入与组件库

## 背景

一开始没有组件市场，组件仍然要能在人与人、机器与机器之间流转，用户也要能管理自己手上的组件：知道它从哪来、用在哪、能不能更新、怎么回退。以后接入市场时，不希望再改一遍格式与流程。

## 决定

- 只有一种组件交换格式：`.dshw`，组件目录原样打成 zip，读写用 fflate。解包前校验：路径不越出组件目录、扩展名在白名单内（html、css、js、json、svg、png、webp、woff2、md、txt）、总大小与文件数不超过上限。**已实现**：`GET /library/widget/<id>/export` 下载，`POST /library/import` 导入；校验不过整包拒绝，不留半个组件。
- 看板交换格式 `.dshboard`：看板标题、每张卡片的盒子与 props，以及用到的全部组件（按哈希内嵌）。实例的 `data` 与 `state` 默认不导出，`?data=true` 才带上。**已实现**：`GET /board/export[?data=true]` 与 `POST /board/import`。
- 同 id 不同内容**不静默覆盖**：先回 409 并带上两边的哈希与现有的来源，调用方带 `replace=true` 再来一次才覆盖。内置与插件提供的组件永远不能被导入覆盖——它们不落在用户目录里（D17）。**已实现**。
- 还没实现的部分：
  - 每个组件记一条来源（`local`、`agent`、`file`、`url`、`plugin`）。现在来源有 `builtin` / `user` / `market` / `plugin` / `example` 五种，`agent` 写出来的组件与用户手写的落在同一个 `user` 来源里。
  - 导入前的权限确认页与尺寸矩阵自检、`url` 与 git 目录导入、检查更新、`forkedFrom` 与「你的副本已修改」。
  - 组件库页面里的版本历史、回退、删除、blob 清理与「被哪些看板使用」。
  - `widget_library` 工具（D9）。
- id 的 `<作者域>.<名字>` 形式用于市场来源，扁平 id 属于本地组件；规则与安装路径见 D30。
- 组件库面板里每一格有「导出」，头部有「导入」（一个 `.dshw` 文件选择器）；导出的是一个普通下载链接，导入之后重读组件库。

## 后果

- 没有市场时，git 仓库加 `url` 来源就能订阅别人的组件。
- 文件里只有哈希清单，没有签名；完整性可以校验，作者身份无法校验，信任靠权限确认页与沙箱。
- 清理 blob 要扫描会话日志，代价随会话数增长，所以只在用户触发时运行。

## 重审条件

- 接入市场或出现需要确认作者身份的分享场景时，加入签名与发布者身份。
