# D9. 面向会话的工具与自检

## 背景

看板要能被任何会话读写：agent 能放置组件、推送数据、编写新组件，并把组件直接显示在回答里。agent 写出的组件在某个尺寸下溢出、报错，它自己看不见；用户发现之后再转述给它，来回一次的代价很高。任务看板插件的经验是：工具只调同一个宿主服务、拒绝以值返回、系统提示只在工具可见时出现。

## 决定

- 七个工具，经 `ctx.tools.register` 注册，跟随总开关注册与撤销。**已实现**：
  - `widget_catalog`：组件类型的说明、尺寸族、props 与 data 的 JSON Schema、来源、提供方与当前版本的哈希；读不出来的目录也列出来并写明原因。
  - `widget_define`：新建或更新组件类型（manifest 与整个目录的文件），返回内容哈希与说明。
  - `widget_show`：把一个组件内联显示在当前会话的回答里。给 `id` 时显示看板上已有的那一张，写状态与发动作都落在它身上；给 `widget`（可带 props 与 data）时按组件起一份一次性快照，不在看板上，状态只留在页面上。两条路径都不改看板。
  - `widget_board`：读一块看板上的卡片（默认选中的那块），同时列出全部看板与它们的 id，供后续调用点名。
  - `widget_place`：往看板上放一张新卡（可以用 `board` 指定另一块看板），或按 id 改一张已有卡的位置、大小、props 与数据源。
  - `widget_remove`：移除一张卡（组卡按组移除）。
  - `widget_push`：向一张卡推送数据。调用最频繁、载荷小，单独一个工具。
- 卡片 id 全工作区唯一：`widget_board`、`widget_place`、`widget_push`、`widget_remove` 都按 id 找卡，跨看板可用，不必先把那块看板切到选中（D21）。
- 带视图的返回值经 `output.presentationMeta` 投影进这次结果的 `meta`，浏览器半边的视图只读它，不再回读宿主；宿主只对顶层调用（不经 `run_code`）投影。视图按线上工具名注册在 `tool.call.toolview` 上，注册过就替换掉具名工具行。
- **还没有的**：`widget_library`（导出、导入、复制、回退、删除、检查更新，D8）。导入与导出已经能用，还差把这些动作做成工具。
- 工具的参数是给模型看的 JSON Schema，执行体自己校验输入（直接注册，不经 `defineTool`——本仓库构建时拿不到 `@deepseek-ai/dsh-tools`，那一包由宿主进程提供）。领域上的拒绝抛出并带上原因，宿主把它收敛成 `isError`；工具描述是面向模型的英文。
- 注册经 `ctx.inject(['tools'], …)`：cordis 只允许读声明过的服务，直接读未声明的属性会抛。`systemPrompt` 与 `skills` 各自等自己的服务，任何一个缺席都不影响工具本身（D1、D11）。
- 编写指南是经 `ctx.skills.register` 注册的虚拟 skill `widget-authoring`：目录格式、manifest 的字段、`window.widget` 的接口、盒子契约（两个方向的档位）、令牌与套件原语、以及几个容易踩空的地方；模型按需加载。
- 系统提示只有一小段说明插件与工具的存在，并且只在工具可见时出现。
- **还没有的**：`widget_define` 的自检（草稿、在线客户端的隐藏画廊、脚本错误与溢出的报告、无客户端时标 `unverified`），以及 `widget_define` 在 `tool.call.toolview` 上的视图。自检要与持续集成的尺寸矩阵共用同一个检查器（D13），而那个检查器现在住在 `packages/testing/matrix.cjs` 里、由 Playwright 驱动，还不能被宿主调用。
- **还没有的**：卡片出错时显示「交给 agent 修复」并把故障报告发进一个会话。

## 后果

- 自检依赖在线的客户端；纯无界面的宿主上，agent 拿到的是未验证的结果。
- 工具数量固定为七个（加上还没有的一个共八个），新能力优先作为已有工具的动作加入，避免工具表膨胀。
- 运行与刷新会消耗用户的额度与本机资源，相关动作的批准规则见 D6。
- agent 写出的组件与用户自己写的落在同一个目录里、走同一份校验；一个组件要动外部世界仍然要人给出授权（D6）。
- 冒烟只能核对「工具在真实宿主里注册上了」（宿主自己的输出是唯一看得见它的地方）；工具的行为由 `packages/host/test/tools.test.ts` 盯着。真正的端到端（会话里让模型写一个组件）要有人在场，不属于冒烟。

## 重审条件

- 宿主提供无界面的页面渲染服务时，自检改在宿主上完成，不再依赖在线客户端。
